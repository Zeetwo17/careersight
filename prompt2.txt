|---|---|---|

The BHM insight should inform how the IPR is structured offline. Everything else is too complex to implement reliably before demo day.

## 2. Consensus Analysis

**What all five critiques agreed on (7 items):**
1. Parser misassignment (correct text, wrong field) is the most dangerous parsing failure
2. IPR coverage gap is the highest-leverage single improvement
3. NIRF rank must not dominate; empirical outcome data must anchor predictions
4. Elite profiles must not collapse to median predictions
5. Streaming SSE judge-facing flow is the right UX pattern
6. All heavy computation must be offline; critical path must be dict lookups + small trees
7. Confidence must be visible per-field and must gate the output band width

**What all critiques missed:**
1. None explicitly operationalised the IPR monthly survival curve storage format and interpolation method
2. None specified the exact fallback when the IPR fuzzy match score is 72–80 (ambiguous band)
3. None addressed what happens when the same document is uploaded twice (idempotency, caching)
4. None specified how `cgpa_percentile_in_cohort` is computed when the IPR has only salary data (not CGPA distributions) — this is a hidden data dependency

**Where critiques conflicted:**

| Conflict | Document 9 | Document 13 | Resolution |
|---|---|---|---|
| Primary parser | Gemini Flash as fast path when available | Replace Gemini Flash with local 0.6B LLM | Keep Gemini Flash; it is faster, free, and has no dependency risk |
| Layout detection | DBSCAN for 3-column support | Full GNN + SRL | DBSCAN wins: same accuracy for 95% of cases, zero additional dependencies |
| BHM | Practical approximation via empirical quantiles | Full MCMC at training | Offline MCMC is correct; empirical IPR is a valid approximation |
| Elite outlier | Weighted signal rule (cumulative ≥5) | Static threshold overrides | Weighted rule wins: continuous, learnable, no hard discontinuities |
| Calibration | Beta calibration (keep) | Kernel-based calibration (replace) | Beta calibration wins: well-validated, <5ms, already implemented |

**Strongest critique overall:** Document 12. It identified the most technically impactful problem that no other critique had named precisely: the salary anchoring formula discards within-institute dispersion by scaling all percentiles with a single factor. The survival-curve-based placement anchoring is also novel and correct. Both are implementable without structural changes to the pipeline.

**Second strongest:** Document 9. Root-cause analysis is the most complete, and the six specific fixes are all implementable, low-risk, and low-latency.

| Contradiction | Options | Resolved Position |

## 4. Decision Matrix

| Design choice | Options | Winner | Reason | Tradeoff |
|---|---|---|---|---|
| Primary parser | Gemini Flash / OpenRouter → heuristic | Keep current cascade | Zero dependency risk; already works; Gemini Flash is fast and accurate | External network call adds 1.5–4s; mitigated by 5s timeout + heuristic fallback |
| Layout detection upgrade | 2-means → DBSCAN | DBSCAN on word x0 coordinates, 3-cluster support | Handles narrow sidebars and 3-column layouts; scikit-learn, zero new dependencies, +2ms | Cannot handle overlapping x-ranges; those cases fall through to LLM which handles garbled text |
| Salary anchoring | Single median scale → quantile-aware percentile shift | Quantile-aware percentile shift with student percentile model | Preserves within-institute dispersion; top-quartile student's range anchors to institute's upper tail, not just shifted median | Requires pre-trained ordinal/percentile classifier; +5ms inference |
| Placement anchoring | Single `placement_rate_6m` blend → monthly survival curve blend | Monthly survival curve blend | Captures institute-specific hazard shape (early vs. late placing institutes) | Requires IPR to store {3m, 6m, 9m, 12m} rates; monotonic interpolation fills months |
| Elite outlier detection | Fixed 5-signal rule → weighted rule | Weighted signal scoring (cumulative weight ≥ 5) | More calibrated; no hard boundary jumps; FAANG PPO + top CGPA always fires | Weights are still heuristic; production version should be learned from real outcome data |
| IPR coverage expansion | Manual curation → NIRF scraper | NIRF scraper (offline, one-time) | Expands 21 → 800+ institutes; no inference change; highest ROI single improvement | NIRF data is self-reported; flag as `data_quality: "inferred"`; log-normal approximation for percentiles |
| Alpha weight refinement | Fixed by fallback level → dynamic by sample_size | Dynamic alpha: `α = min(0.8, 0.4 + 0.004 × sample_size)` | Rewards large sample sizes; penalises thin data; principled rather than arbitrary | Requires storing sample_size in IPR (already present) |
| SHAP background | Synthetic corpus → IPR-calibrated | IPR-calibrated background | Correct baselines = correctly scaled attributions; <5ms to build, pre-loaded | Construction requires joint feature distribution per institute; use IPR quantiles for salary features, synthetic distribution for others |
| Scanned PDF handling | Hard reject → OCR path | OCR async path with visible status | Reject-on-scan excludes valid candidates from less-digitally-savvy backgrounds | Tesseract adds 4–8s on CPU; async with visible status message masks this |
| DeepHit cold-start | Lazy load → pre-warm at startup | Pre-warm dummy call at startup | Eliminates 2.5s stall for first request after idle | +2.5s at startup; mitigated by health-check cron ping |
| Cross-field validator | None → deterministic rules | 5-rule consistency validator (post-parse) | Catches misassignment without re-extraction; <5ms; catches the most common silent failure mode | Cannot catch all misassignments; false penalty possible for legitimate edge cases (e.g., institutes with company-like names) |
| Feature uncertainty propagation | Gate on output band width only → also feed to model | Uncertainty features as both band-width gate AND model inputs | Model learns to be conservative when parse confidence is low; more honest predictions | Small risk of model learning to be unconservative on all profiles; regularise |

## 5. Red-Team Validation Results

**Case 1 — Non-resume PDF (course brochure with email + bullet points)**
What happens: Validity gate scores structural signals (email: +1, bullet ratio: +1, section headers: 0 or +1 if PDF has "Programme Overview"). May score 0.35–0.55. Falls in ambiguous band → lightweight logistic classifier fires → trained classifier should detect heavy prose ratio, long paragraph blocks, missing personal pronouns, academic vocabulary ("prerequisites", "semester", "credits"). Result: rejected with evidence. Works correctly if the classifier is trained with project reports and brochures as hard negatives.
**What fails:** If the brochure is formatted exactly like a resume (rare but possible). Semantic check (proportion of academic terms "abstract", "introduction", "literature review") adds another negative signal.
**Fix:** Add semantic negative signals to validity gate. Worth it: yes, +5ms, high trust value.

**Case 2 — Resume with unusual formatting (Canva two-tone template, name in right column in large font)**
What happens: 2-means or DBSCAN detects two columns. Left column text and right column text separated correctly. Name in right column at large font → font-size signal in name extractor identifies it as `max(word['size'])` on page 1. Three-strategy majority vote (NER + font-size + contact-block proximity) finds name in right column.
**What fails:** If the name is embedded as a vector graphic (not text). All three strategies return null. Result: name confidence = 0.0, amber badge in UI. Judge can correct inline.
**Fix:** If name not found, set confidence 0.0, show amber badge "Name not detected — click to enter." Do not fabricate.

**Case 3 — Scanned / image-only PDF**
What happens: pdfplumber extracts < 150 characters → `image_heavy = True`. Currently: validity gate flags, profile is empty, no scoring. NEW behaviour: SSE emits `"Scanned document detected — applying OCR (a few extra seconds)"`. Async Tesseract call. If OCR succeeds with ≥ 500 characters, continue to parser cascade. If OCR fails (garbled text), show "Paste your resume text" panel.
**What fails:** OCR quality on low-resolution scans is unreliable. If the OCR text is garbled enough, the parser extracts nonsense fields with medium confidence (not caught by validity gate, which already accepted the document).
**Fix:** After OCR, re-run the semantic zone and cross-field consistency validator. If both fail (no sections detected, all fields low confidence), route to "paste text" fallback. Accept the 4–8s latency for this path with a visible status message.

**Case 4 — Multi-column resume with narrow left sidebar**
What happens: 1D 2-means fails because sidebar has <30% of words → treated as single column → skills from sidebar get interleaved with experience from main column. NEW behaviour: DBSCAN on x0 coordinates with ε = 30px detects narrow cluster (sidebar) + wide cluster (main body) regardless of word count ratio. Left column read top-to-bottom first, then right column.
**What fails:** DBSCAN cannot distinguish overlapping x-ranges if sidebar and main body overlap horizontally. In that case, falls through to LLM cascade which handles garbled text reasonably.
**Fix:** If DBSCAN finds clusters with overlapping x-ranges, mark `layout=complex`, pass full text to LLM cascade with a "complex layout detected" note in the prompt. Acceptable.

**Case 5 — Document with missing section headers**
What happens: Section-zone detector finds zero headers → falls back to unconstrained extraction → all field confidences reduced by 0.2 uniformly → cross-field consistency validator still runs. Most fields still extract correctly for simple single-column resumes without headers.
**What fails:** Misassignment rate increases because zone constraints are absent. Institute name may be confused with employer name.
**Fix:** Uniform -0.2 confidence reduction is already specified. For critical fields (institute, degree), fall to multi-strategy extraction with explicit cross-field checks. Acceptable — this is the right degradation path.

**Case 6 — Ambiguous identity extraction**
What happens: Three-strategy name extraction (spaCy PERSON NER + font-size signal + contact-block proximity) runs. Scenario: two names found (candidate + manager reference). Font-size signal picks the largest text. Contact-block proximity picks the text above the email. If both point to the same token → confidence 0.85+. If they disagree → confidence 0.40, amber badge.
**What fails:** Resumes that list a reference name at the top in large font (rare but exists). Cross-field consistency validator: if extracted name matches any known institute name, skill term, or company name → reduce confidence by 0.4.
**Fix:** The deny-list check handles the main failure mode. Residual ambiguity shows as amber badge.

**Case 7 — Ambiguous institution extraction**
What happens: Section-zone detector finds Education zone. Multi-evidence extraction runs: all proper-noun sequences in Education zone, fuzzy matched against IPR alias map. If highest match score = 85, top-1 is accepted. If highest match score = 72–80, surface disambiguation: "Did you mean: (1) [Match A] (2) [Match B]? Click to confirm." Judge confirms. Post-confirmation, confidence = 1.0.
**What fails:** In a live demo where the judge isn't interacting (automated test), no confirmation is given and the system must choose. Use top-1 with confidence = 0.55.
**Fix:** Automated fallback: use top-1, confidence = 0.55, IPR `data_quality = "low"`, salary range widened by 1.20×. Surface amber banner.

**Case 8 — Known institute, branch unclear**
What happens: IPR lookup falls to L2 (institute + degree, all branches). Salary range is wider (institute aggregate across all branches). Confidence badge in IPR card: "Branch not detected — using institute-wide data." Risk model still has access to all 59 other features.
**What fails:** A B.Tech Civil student and B.Tech CS student from the same institute have very different placement profiles; L2 average blends both. `branch_demand_index` feature is unavailable.
**Fix:** If branch is not found, set `branch_demand_index = national_average` and show amber badge "Branch not detected". The model still distinguishes through skills extracted. Acceptable degradation.

**Case 9 — Sparse-data institution (regional private college, not in IPR, not in NIRF top-1000)**
What happens: IPR lookup fails L1–L3. L4 cluster lookup triggers: `tier × degree × branch_family`. Salary range widened by 1.15×. Data quality = "low". Amber warning banner. Judge sees "Using national estimates for [tier] [branch] colleges — limited institute-specific data."
**What fails:** If the student is an outlier from a weak institute, the L4 cluster may still give a reasonable range, but it won't capture the specific institute's actual distribution. This is an inherent data limitation, not a design flaw.
**Fix:** The 1.15× widening and the explicit banner are honest and correct. No fix needed beyond the NIRF scraper expansion (which may bring this institute to L2/L3).

**Case 10 — Exceptional high-achieving profile (FAANG PPO + national CP rank + 9.5 CGPA + GSoC)**
What happens: Elite outlier scoring: FAANG PPO internship = 3, national CP rank = 3. Total weight = 6 ≥ threshold of 5. Elite branch fires. Salary lower bound = `ipr_p75` instead of `ipr_p10`. Upper bound = uncapped. Quantile-aware anchoring: student percentile = 0.95 (CGPA top 5% + internship brand + CP rank). `predicted_p50 = ipr_percentile_at(95)` ≈ near p90. Result: salary range anchored to institute's upper tail.
**What fails:** If the IPR has too few data points at the p90, the percentile interpolation may be noisy. 
**Fix:** For elite flag + n < 50 in IPR, revert to `lower_bound = ipr_p75`, `upper_bound = 2 × ipr_p90` (the current architecture's approach for L1 elite cases).

**Case 11 — Profile that should not be underpredicted (strong regional institute, not in IPR)**
What happens: Falls to L4 cluster. Cluster average for "Tier-2 state technical university + CSE" may underestimate if this institute's actual placement is stronger than its tier peers.
**What fails:** The NIRF scraper (Fix 3) would have caught this if the institute is in NIRF top-1000. If it is not, the L4 cluster is the best available.
**Fix:** After NIRF scraper runs, this institute gets L2 data with `data_quality: "inferred"`. Acceptable.

**Case 12 — Profile that should not be overpredicted (reputed brand name institute, weak actual placements)**
What happens: IPR lookup finds the institute at L1 with actual placement data. Actual data shows weak placement rates (say 45% at 6m) and lower salary distribution. Model uses real IPR data, not brand reputation. This is exactly the problem the IPR was designed to solve.
**What fails:** Nothing, if the IPR has correct data. If the NIRF scraper ingests inflated self-reported data, the IPR itself is wrong.
**Fix:** Tag NIRF-scraped entries as `data_quality: "inferred"`. When `data_quality = "inferred"`, set `α = 0.5` rather than 0.7 for blending.

**Case 13 — Low parser confidence (scanned, OCR degraded, section headers missing)**
What happens: `parse_confidence_mean < 0.50` → salary band widened by 1.20×. `parse_confidence_min < 0.30` → salary band widened by additional 1.10×. Uncertainty features fed to model. UI shows amber badges on every field.
**What fails:** If the user proceeds with a degraded parse, the score may be unreliable even with widened bands.
**Fix:** When `parse_confidence_mean < 0.40`, surface a persistent amber banner: "Prediction quality limited — resume content was hard to read. Enter details manually for a more accurate estimate." Include inline edit fields.

**Case 14 — Conflicting signals across document (internship listed in multiple sections with different durations)**
What happens: Multi-evidence extraction finds two mentions of the same employer with different months. Cross-field consistency validator fires rule: if two internship entries for same employer have conflicting dates, flag both as `confidence -= 0.3`. Output: "Internship: Flipkart (duration unclear)" with amber badge.
**What fails:** If the document lists two separate Flipkart internships legitimately, the validator incorrectly penalises both.
**Fix:** Before penalising, check if the date ranges are non-overlapping (could be two legitimate internships). If non-overlapping, accept both; if overlapping, flag conflict.

**Case 15 — Duplicate or noisy pages**
What happens: Text hash deduplication is already in `pdf_extract.py`. Duplicate pages are dropped before parsing. Works correctly.
**What fails:** Near-duplicate pages (same content, minor differences) won't match on hash. Unlikely to cause real problems — parser would extract the same fields twice and keep the first.
**Fix:** No fix needed; this is a low-probability edge case with low impact.

## 6. Recommended Improved Architecture

The improved architecture retains the five-stage pipeline and adds six targeted modifications.

**Stage 0 — Pre-flight (unchanged, < 50ms)**
Magic bytes + size check + emit `upload` SSE event.

**Stage 1 — Validity Gate v2 (< 80ms)**
Keep the 8+2 rule-based signal scoring for the clear bands. Add two new negative signals:
- `academic_document_score`: proportion of text tokens from an academic vocabulary list ("abstract", "introduction", "methodology", "references", "literature review", "keywords") that is not in any resume-positive section. If this proportion > 0.15 and the document has no internship/experience section, add -0.3 penalty.
- `continuous_prose_ratio`: ratio of lines longer than 80 characters to total lines. Resumes have few long prose lines (mostly bullet points). If > 0.4, add -0.2 penalty.

Add a 50-feature logistic classifier (TF-IDF top-25 unigrams + structural features) that fires only in the ambiguous band (0.30–0.75) to resolve edge cases. Below 0.30 → hard reject. Above 0.75 → hard accept. 0.30–0.75 → classifier decides.

**Stage 2 — Layout-Aware Extraction v2 (< 100ms/page)**
Replace 1D 2-means with DBSCAN on `(x0, x1)` word coordinates (ε = 25px, min_samples = 5). DBSCAN naturally handles 3-column layouts, narrow sidebars, and irregular spacing without a minimum-cluster-size constraint.
Add: `layout_cluster_count` to SSE events ("Three-column layout detected — reading left, center, right columns in order").
Async OCR path: if `image_heavy = True`, trigger Tesseract asynchronously and emit `scanning_document` SSE event. Continue SSE stream with other stages where possible. Merge OCR text when ready.

**Stage 3 — Parser Cascade v2 + Cross-Field Validator (< 50ms after LLM)**
Keep LLM cascade as-is. After parse output, run two new post-parse steps:

*Name disambiguation (10ms):*
Three-strategy majority vote: (1) spaCy PERSON NER on first 400 chars, (2) `max(word['size'])` text from pdfplumber page 1, (3) text immediately preceding email pattern. Accept if ≥ 2 strategies agree. Otherwise, `field_confidence["name"] = 0.40`.

*Cross-field consistency validator (5ms):*
Five rules with hard confidence penalties (not nullification):
1. Institute ≠ known employer (against 10k-company list): both → –0.4
2. CGPA outside [0.0, 10.0]: flag as extraction error, normalise or null
3. Graduation year outside [2015, 2030]: –0.4 on year, propagate to salary widening
4. Name matches known institute name or skill term: –0.4 on name field
5. Degree keyword and branch keyword in same field: –0.3 on branch field

*Semantic zone detection (5ms):*
Detect section headers (line matching ≥ 1 of 80+ header keywords, no comma/period/digit, followed by ≥ 2 lines). Constrain field extraction to correct zones. If no zones detected: uniform –0.2 on all field confidences.

**Stage 4 — IPR Lookup v2 (< 5ms)**
Keep 5-level fallback ladder. Add:
- Dynamic alpha: `α = min(0.80, 0.40 + 0.004 × sample_size)` — rewards large sample sizes
- Store monthly survival curve: {1m, 2m, 3m, 6m, 9m, 12m} placement rates via monotonic interpolation from existing {3m, 6m, 12m} data points
- User confirmation trigger: if rapidfuzz score = 70–80 (below current 80 threshold), surface top-2 candidates with disambiguation question rather than silently using top-1
- IPR now has 800+ institutes after NIRF scraper; `data_quality: "inferred"` for NIRF-derived entries

**Stage 5 — Scoring v2 (< 150ms warm)**
*Salary (quantile-aware):*

## 7. Salary and Risk Modeling Strategy

**Salary: Quantile-aware, prior-first, elite-aware**

The core failure in the current salary model is that anchoring blends only the median and scales all five percentiles by the same factor. This is wrong. A student at the 85th percentile of their cohort should have their p75–p90 anchored to the institute's p75–p90, not their median scaled up by a single multiplier.

The fix: a pre-trained **student percentile model** (ordinal LightGBM or simple quantile regression) estimates the student's percentile rank within their institute × branch × graduation-year cohort. This model is trained offline on historical alumni data and is part of the bundle. At inference it runs in <5ms.

Then, for each quantile q, the blending weight is highest when q is near the student's predicted percentile. A student at the 85th percentile gets their p75–p90 blend heavily from the IPR (real outcomes), while their p10–p25 blend comes mostly from the raw model. This preserves within-institute dispersion correctly.

For L3–L5 fallback cases (where IPR data is sparse), the quantile model cannot be anchored reliably and the LightGBM residual prediction takes over. The salary band widens proportionally.

For the elite branch, `lower_bound = ipr_p75` is the floor. No ceiling applies. Display: "This profile may reach ₹X–₹Y based on top-tier profiles at this institute."

**Placement risk: survival-curve blend, monotone-enforced**

Replace the single `placement_rate_6m` blend with a monthly survival curve blend. The IPR stores {3m, 6m, 9m, 12m} placement rates (already present); monotonic interpolation fills months 1, 2, 4, 5, 7, 8, 10, 11. DeepHit outputs a 13-point monthly survival curve. Blend each point with the corresponding IPR curve point using dynamic α. The blended curve is guaranteed monotone by post-processing (Isotonic regression on the blended values).

This captures institute-specific hazard shapes: an institute that places 80% within 3 months has a dramatically different risk profile than one that places 80% by 12 months, even if the final 12-month rate is the same. The current architecture cannot distinguish these.

CRC threshold: set default FNR ≤ 0.10 for the high-risk classification. Expose as configurable parameter. Document in lender admin panel.

## 8. Parsing and Extraction Strategy

**Core principle: Parse-then-verify, not parse-and-trust.**

The LLM or heuristic parser produces a first-pass profile. The cross-field consistency validator then audits it. The confidence assignment system scores each field based on four independent signals. The result is a profile where confidence reflects actual extraction quality, not just presence.

**Zone-constrained extraction (new):**
Section headers are detected first. Fields are extracted within their expected zones. Violation of zone constraints reduces confidence. No zone detected → uniform –0.2 on all confidences.

**Multi-evidence name extraction (new):**
Three strategies must agree before high confidence is assigned. Font-size signal is the most reliable for creative templates. Contact-block proximity is the most reliable for plain templates. NER catches formal English names. When all three agree → confidence 0.90+. Two agree → confidence 0.70. One → confidence 0.40. Zero → confidence 0.0, amber badge, inline edit.

**DBSCAN layout detection (upgrade):**
Replace 2-means with DBSCAN (ε=25px, min_samples=5) on word `(x0, x1)` coordinate pairs. Supports 1, 2, and 3-column layouts. Narrow sidebar correctly isolated as its own cluster. For overlapping x-ranges (layout=complex), pass full text to LLM with layout hint.

**OCR path (new):**
`image_heavy = True` → async Tesseract call → emit `scanning_document` SSE event → merge OCR text when ready → continue with parser cascade. If OCR text < 200 chars → "Paste text" fallback. OCR adds 4–8s for scanned documents; this is honest, visible, and acceptable.

**Scanned PDF graceful path (new):**
The `rejected` SSE event for image-heavy documents is replaced with `scanning_document` → OCR → continue. Rejection only occurs if OCR fails to produce usable text.

**Adaptive pacing controller:**
```python
PACE_TARGET = 0.40  # seconds per SSE event
remaining_budget = 3.5  # total pacing budget in seconds
for event in events:
    stage_start = time.time()
    yield event
    stage_duration = time.time() - stage_start
    sleep_needed = max(0, PACE_TARGET - stage_duration)
    sleep_needed = min(sleep_needed, remaining_budget)
    remaining_budget -= sleep_needed
    await asyncio.sleep(sleep_needed)
```
This ensures total pacing budget = 3.5s regardless of whether individual stages are slow or fast.
